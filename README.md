# Surrey City Centre campaign map

A static dashboard for the Surrey City Centre provincial riding: supporters found against the votes needed to win, polls shaded by the 2024 result, supporters found, voters not contacted or 2024 supporters who didn't vote, and every contacted household on a labelled street map with one simple filter.

**The page is password-protected.** The team's campaign data (Poll Summary, Interactions and the 2024 supporter voted / did-not-vote lists, with voter names, phone numbers, voter IDs, notes and canvassers removed) is in `data/campaign.enc.js`, encrypted with AES-256-GCM under a key derived from the team password (PBKDF2-SHA256, 600,000 iterations). Without the password the file can't be read, so copying the site or this repository yields nothing usable. Data added since is in `data/campaign.extra.enc.js`, locked with the same key: the phone-bank (T2) households, the door-knocked houses, and the voters file of our supporters on the voters list (voter number, name and address; no phone numbers), which the maps use to read participation reports and to look up whether someone has voted. Everything else is public: `data/public.js` is built from BC open data: Elections BC 2024 boundaries, voting areas, registered voter counts, results by voting place and the poll-to-voting-place assignment; the BC Digital Road Atlas; and BC Address Geocoder address points.

Open the page and enter the team password. The data is decrypted in your browser only, and no campaign data or loaded file ever leaves it: the page's Content-Security-Policy allows no outbound connection except the sign-in log below. Closing the tab locks it again. You can also load newer exports (.xlsx) from your own device; they stay in that tab.

**Who has voted.** Load the Elections BC voting participation report (`VotingParticipationReport….csv`) on either map; nothing needs publishing. Each report adds to the ones already loaded, so load each new one as it comes. The list follows the tab between the two maps and is dropped when you lock or close it. Both maps then show how many have voted in each poll and where. Each map's **Voted** tab has the totals (everyone who has voted against the registered voters, and how many of our supporters), turnout poll by poll, and "has someone voted?" by name and address. Our supporters are matched to the report by voter number, which is never shown or searched on the maps. Routes, focus scores and T1 households leave out our people the report shows have voted; where a unit has several of our people and only some are in the report, the report can't say which ones, so only that many are taken off.

**Sign-in log.** Each time someone unlocks either map with the password, the page adds one line to `signins` in the campaign's Firebase Realtime Database (`desk-config.js`): the time, which map, a random device ID the browser keeps, the browser and device type, and the internet address (looked up from [ipify](https://www.ipify.org), since a page can't see its own). Reloading or switching maps in the same tab isn't a new sign-in. Nothing else is sent, and a log that can't be sent never stops the map opening. Read it in the Firebase console under Realtime Database → Data → `signins`. Before relying on it, publish `database.rules.json` under Realtime Database → Rules: the desk keeps its board, and the log can be added to from the website but read only in the console. The log shows sign-ins through the website. It can't see someone who copies the encrypted files and opens them with the password elsewhere, and a private window or a cleared browser shows up as a new device.

Libraries: [Leaflet](https://leafletjs.com) 1.9.4 and [SheetJS](https://sheetjs.com) 0.20.3, vendored in `vendor/`.
